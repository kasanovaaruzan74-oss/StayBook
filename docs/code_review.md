# Кодты тексеру нәтижелері

№7 зертханалық жұмыс аясында нақты кодта мына тұстар қаралды:

- Сұраулар `Depends(get_session)` арқылы бөлек сессия алады, `with Session` оны жабады.
- `IntegrityError` кезінде rollback жасалып, қайшылыққа 409 қайтарылады.
- Іздеу және сүзгілер параметрленген SQLModel сұрауларын қолданады; LIKE таңбалары автоматты экрандалады.
- PATCH тек берілген өрістерді өзгертеді, міндетті өрістерге айқын null қабылдамайды.
- Брондау жаңартылғанда ескі және жаңа мәндер бірге тексеріледі. SQLite жазу транзакциясы қабаттасатын брондауларды тексеру мен сақтауды қамтиды.
- DELETE жауаптарының 204 мәртебесінде жауап денесі жоқ. Байланысқан негізгі жазбаларды өшіру 409 арқылы тоқтатылады.
- API және UI тесттері негізгі жұмыс базасына әсер етпейді.

## Табылған және түзетілген ақау

Алғашқы Docker нұсқасы іске қосылған сайын `python seed.py` шақырды. Пайдаланушы мысал қонақтың email-ін өзгертіп, телефон нөмірін сақтаса, келесі seed сол телефонмен жаңа қонақ қосуға тырысып, UNIQUE қатесін туғызды. Сондай-ақ жойылған мысал жазбалар қайта пайда болуы мүмкін еді.

Түзету: Docker іске қосылғанда `python seed.py --if-empty` қолданылады. Кестелер құрылады, бірақ төрт кестеде де жазба болмаған кезде ғана мысалдар қосылады. Қолданыстағы деректер өзгермейді.

Бұл ақауға жеке регрессиялық тест қосылды: бастапқы деректерді құру, қонақ email-ін өзгерту, бір брондауды жою, скриптті қайта орындау және өзгерістердің сақталғанын тексеру. Толық Docker down/up циклінде де түзету нақты тексерілді.
