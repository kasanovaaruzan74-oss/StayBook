# Қорғауға арналған бақылау сұрақтары

Жауаптар бастапқы нұсқаулықтағы №1–4 жұмыстардың 20 бақылау сұрағына сәйкес реттелді. Мысалдар StayBook жобасына бейімделді.

## Зертханалық жұмыс №1

### 1. Python жобасында виртуалды орта не үшін керек? Оны құрмасақ не болады?

`venv` бір жобаның Python пакеттерін басқа жобалардың пакеттерінен бөледі. StayBook тәуелділіктері сол ортаға орнатылады. Онсыз жүйелік Python ортасында кітапхана нұсқалары қайшы келуі, бір жобаны жаңарту екіншісін бұзуы мүмкін. Виртуалды орта Python нұсқасын өзі орнатпайды, ол таңдалған Python интерпретаторының негізінде жасалады.

### 2. `.gitignore` не үшін қажет? Неліктен оған `venv` және парольдері бар файлдар қосылады?

`.gitignore` Git-ке әлі тіркелмеген қандай файлдарды бақылауға алмау керегін көрсетеді. Виртуалды орта үлкен әрі басқа компьютерде қайта орнатылады, ал құпия конфигурация жарияланбауы тиіс. Жобаға `venv/`, `.venv/`, `.env`, `*.db`, `__pycache__/` кірмейді. Бұрын Git-ке қосылған файлды `.gitignore`-ға жазу оны тарихтан автоматты алып тастамайды.

### 3. Cursor немесе ИИ плагині қандай қызмет атқарады? ИИ кодын тексермей көшірудің тәуекелі қандай?

ИИ көмекшісі жоба құрылымын ұсынуға, модель мен API кодын жазуға, қатені түсіндіруге және тест дайындауға көмектеседі. Әзірлеуші берілген кодтың логикасын тексереді, қолданылған кітапхананың құжатымен салыстырады және іске қосады. Тексерілмеген код ескірген API-ді, қате байланыстарды, қауіпсіз емес сұрауларды немесе орындалмайтын функцияларды қамтуы мүмкін.

### 4. Git тармағы деген не? Неліктен командалар негізгі тармаққа тікелей жазуды шектейді?

Тармақ — коммиттер тарихындағы бөлек бағытты көрсететін сілтеме. `git branch feature/room-filters` жаңа тармақ жасайды; `git switch -c feature/room-filters` оны жасап, соған ауыстырады. Командаларда `main` жиі қорғалады: өзгеріс бөлек тармақта жазылып, pull request пен тексерулерден кейін біріктіріледі. Бұл барлық жобадағы Git-тің міндетті тыйымы емес, репозиторийдің жұмыс тәртібі.

### 5. `git commit` пен `git push` айырмасы неде? Өзгерістер қайда сақталады?

`git commit` индекске қосылған өзгерістердің нұсқасын жергілікті `.git` тарихына сақтайды. `git push` жергілікті коммиттерді GitHub сияқты қашықтағы репозиторийге жібереді. Тек commit жасалса, өзгеріс басқа компьютерлерде әлі көрінбейді. `git add` файлдарды келесі коммитке дайындайды.

## Зертханалық жұмыс №2

### 1. ORM деген не және ол қандай мәселені шешеді?

ORM — Object-Relational Mapping, Python объектілерін реляциялық кестелермен сәйкестендіру. SQLModel ішінде `Room` класының объектісі `rooms` кестесінің жазбасына сәйкес келеді. Әзірлеуші негізгі дерек әрекеттерін Python кластары және сұрау құрылымдары арқылы орындайды. Дегенмен SQL, транзакция және дерекқор байланыстарын түсіну қажет болып қалады.

### 2. `category_id` пен `category` Relationship өрісінің айырмасы қандай?

`category_id` — `rooms` кестесінде сақталатын нақты сыртқы кілт бағаны. Ол `room_categories.id` мәніне сілтейді. `category` — тиісті санат объектісіне қатынауға арналған ORM байланысы; оның атымен қосымша SQL бағаны жасалмайды. Бірінші өріс кілт мәнін, екіншісі Python объектілері арасындағы қатынасты береді.

### 3. Seed деректер не үшін қажет? Бос базамен жұмыс неге ыңғайсыз?

Seed — жүйені алғашқы үлгі деректермен толтыру. Қонақтар, санаттар, нөмірлер мен брондаулар болғанда API тізімін, сыртқы кілттерді, сүзгілерді және қайшылықтарды бірден тексеруге болады. Бос база дұрыс сүзгі мен қате сүзгінің екеуіне де бос тізім қайтарып, мәселені жасыруы мүмкін. StayBook-та `python seed.py` бастапқы деректерді енгізеді, қайта іске қосу бірдей жазбаларды көбейтпейді.

### 4. `create_engine` ішіндегі `echo=True` қандай рөл атқарады?

Бұл параметр орындалатын SQL сұрауларын және транзакция логтарын консольге шығарады. Кесте жасалғанын, дұрыс `SELECT` немесе `INSERT` орындалғанын көруге көмектеседі. StayBook-та оны `SQL_ECHO=1` арқылы қосуға болады. Логты қарағанда енгізілген деректердің де көрсетілуі мүмкін екенін ескереміз.

### 5. Неліктен `database.db` Git-ке кірмейді, ал `models.py` міндетті түрде кіреді?

`models.py` деректер құрылымын анықтайтын бастапқы код, сондықтан өзгерістері бақыланады. `database.db` — жұмыс барысында өзгеретін жергілікті деректер файлы; ол көлемді болуы, жеке мәлімет қамтуы және біріктіру қайшылығын туғызуы мүмкін. Құрылым `init_db()`, ал мысал мазмұн `seed.py` арқылы қайта құрылады.

## Зертханалық жұмыс №3

### 1. REST API деген не? GET пен POST айырмасы қандай?

REST API ресурстарға HTTP арқылы қатынауды ұйымдастырады. StayBook-та ресурстар — `/rooms`, `/guests`, `/bookings`. `GET` деректі оқиды және сервер күйін өзгертпеуі тиіс. `POST` көбіне жаңа ресурс жасайды; сұрау денесіне жаңа жазбаның деректері жіберіледі және сәтті жасағанда `201 Created` қайтады.

### 2. FastAPI ішіндегі Pydantic не істейді? Ол қате енгізуден қалай қорғайды?

Pydantic сұрау өрістерінің типтерін, шектерін және өзара шарттарын тексереді, сондай-ақ жауап құрылымын сипаттауға көмектеседі. Мысалы, теріс `price_per_night`, нөлдік `capacity` немесе бос `room_number` қабылданбайды. Схемаға сәйкес емес сұрауға FastAPI `422` қайтарады. Бұл логин мен пайдаланушы құқықтарын тексеруді алмастырмайды.

### 3. `Depends` деген не? Неге барлық маршрутқа бір ортақ сессияны импорттамаймыз?

`Depends` — тәуелділікті енгізу механизмі. `Depends(get_session)` маршрутқа оның сұрауына арналған сессияны береді. Генератор сессияны ашып, өңдеуден кейін жабады. Бір ортақ ұзақ өмір сүретін `Session` параллель сұраулардың транзакцияларын араластырып, қате күй қалдыруы мүмкін. Ал `engine` объектісін ортақ пайдалану қалыпты: engine мен Session бір ұғым емес.

### 4. Swagger UI қалай жасалады? Оның HTML кодын қолмен жазу қажет пе?

FastAPI маршруттардан, типтерден және Pydantic схемаларынан OpenAPI спецификациясын жасайды. Дайын Swagger UI сол спецификацияны қолданып, интерактивті құжаттаманы көрсетеді. Қолмен HTML жазу қажет емес. StayBook үшін мекенжай — `http://127.0.0.1:8000/docs`, спецификация — `/openapi.json`.

### 5. `422 Unprocessable Entity` қашан қайтады?

Сұрау форматы түсінікті болғанымен, оның өрістері қабылдау схемасына сәйкес болмағанда `422` қайтады. Мысалы, теріс баға, жарамсыз күн, міндетті өрістің болмауы немесе міндетті өріске `null` жіберу. Бұл `404`-тен өзгеше: `404` дұрыс пішіндегі ID-мен ізделген ресурс табылмағанын білдіреді.

## Зертханалық жұмыс №4

### 1. PUT пен PATCH айырмасы қандай? Қайсысы трафикті азайтуы мүмкін?

`PUT` ресурстың толық көрінісін ауыстыруға, `PATCH` оның бір бөлігін өзгертуге арналған. Нөмірдің тек бағасын өзгерту үшін PATCH сұрауымен бір өріс жіберу жеткілікті, сондықтан мұндай жағдайда трафик аз болады. Барлық жағдайда бір әдіс аз трафик береді деген ереже жоқ: ол жіберілетін дерек көлеміне байланысты.

### 2. Query параметрлері деген не және URL ішінде қалай беріледі?

Query параметрлері URL жолындағы `?` таңбасынан кейін жазылады, бірнешеуі `&` арқылы бөлінеді. Мысалы: `/rooms?search=10&min_price=10000&max_price=30000`. Олар ресурсқа қосымша іздеу не сүзгі шарттарын береді. Нөмірдің ID-і `/rooms/5` түрінде берілсе, ол query емес, path параметрі болады.

### 3. PATCH кезінде None мәндерінен қалай қорғанамыз?

`model_dump(exclude_unset=True)` клиент жібермеген өрістерді жаңарту сөздігінен алып тастайды. Бірақ клиент нақты `null` жіберген өріс бұл сөздікке кіреді. Сондықтан міндетті өрістерге `null` мәнін схема валидаторымен қабылдамаймыз; дерекқордың `NOT NULL` шектеуі қосымша қорғаныс береді. `Optional` жалғыз өзі бұл мәселені шешпейді. `exclude_none=True` қолдану барлық жағдайда балама емес: кейбір рұқсат етілген өрістерді клиент әдейі босатуы мүмкін.

### 4. Жою алдында ID бойынша жазбаны не үшін іздейміз?

Алдымен жазбаның бар-жоғын біліп, табылмаса түсінікті `404` қайтарамыз. Сонымен бірге бизнес шарттарын тексереміз: мысалы, брондауы бар нөмірді жоймау. Базаның сыртқы кілттері мен транзакциялар да қажет; алдын ала іздеу дерекқор шектеулерін алмастырмайды.

### 5. CRUD деген не? Қандай HTTP әдістері сәйкес келеді?

| Әрекет | Мағынасы | HTTP әдісі |
|---|---|---|
| Create | Жаңа жазба қосу | `POST` |
| Read | Тізімді немесе бір жазбаны оқу | `GET` |
| Update | Жазбаны толық немесе ішінара өзгерту | `PUT` немесе `PATCH` |
| Delete | Жазбаны жою | `DELETE` |

StayBook-та ішінара жаңарту `PATCH` арқылы іске асырылады.
