# Зертханалық жұмыс №3

**Тақырып:** FastAPI арқылы серверлік REST API жасау.

## Мақсат

Дерекқордағы мәліметті HTTP арқылы оқу және қосу, сұрауларды валидациялау, әр сұрауға бөлек сессия беру және Swagger UI арқылы API-ді көрсету.

## 1. Қолданбаны іске қосу

Виртуалды орта белсенді болуы керек. Алдымен мысал деректерді дайындаңыз:

```bash
python seed.py --if-empty
uvicorn app.main:app --reload
```

`app/main.py` FastAPI қолданбасын жасайды, lifespan кезінде `init_db()` шақырады және роутерлерді қосады. `GET /` сервердің күйін хабарлайды.

Дұрыс мекенжайлар:

- сервер: <http://127.0.0.1:8000/>;
- Swagger: <http://127.0.0.1:8000/docs>.

Бастапқы нұсқаулықтағы `http://127.0.0` толық емес; стандартты uvicorn порты — `8000`, Swagger жолы — `/docs`.

## 2. Сессияны тәуелділік арқылы алу

`app/database/db.py` ішіндегі `get_session()` функциясы сессияны ашады, `yield` арқылы маршрутқа береді және сұраудан кейін жабады. Маршрутта `Depends(get_session)` қолданылады. Барлық сұрауға бір ортақ ашық `Session` объектісін пайдалану дұрыс емес: транзакциялар мен сұраулар араласып кетуі мүмкін.

## 3. GET маршруттары

`app/routers/` бөлімінде:

- `GET /rooms` — нөмірлер тізімі;
- `GET /rooms/{room_id}` — ID бойынша нөмір;
- жоқ ID үшін `404 Not Found`.

Қосымша `/guests`, `/categories`, `/bookings` маршруттары байланысты деректерді дайындауға және көрсетуге арналған.

ИИ сұрауының үлгісі:

> FastAPI және SQLModel көмегімен нөмірлер тізімін және ID бойынша бір нөмірді қайтаратын GET маршруттарын жаз. Сессияны Depends(get_session) арқылы ал. Жазба табылмаса HTTPException 404 қайтар. Жауап схемасын ORM моделінен бөлек анықта.

## 4. POST және валидация

`app/schemas.py` ішінде клиенттен келетін дерекке арналған құру схемалары және жауап схемалары бөлек беріледі. Клиент бастапқы кілтті өз бетімен орнатпайды.

`POST /rooms` мысалы:

```json
{
  "category_id": 1,
  "room_number": "DEMO-601",
  "price_per_night": "22000.00",
  "capacity": 2
}
```

`category_id=1` базада болуы керек. Сәтті қосылған жазба `201 Created` күйімен қайтады. Теріс баға, бос атау/белгі немесе жарамсыз сыйымдылық `422` қатесін беруі керек. Бірегей нөмір белгісінің қайталануы — `409 Conflict`.

ИИ сұрауының үлгісі:

> Нөмір қосатын POST /rooms маршрутын жаса. Баға теріс болмасын, нөмір белгісі бос болмасын, сыйымдылық кемінде бір болсын. Санат бар екенін тексер. Жазбаны session.add/commit/refresh арқылы сақтап, 201 мәртебесін қайтар. Қате транзакцияда rollback жаса.

## 5. Swagger арқылы көрсету

1. `/docs` ашып, `GET /rooms → Try it out → Execute` таңдаңыз.
2. `GET /rooms/{room_id}` ішінде тізімдегі ID-ді көрсетіңіз.
3. Теріс бағамен жаңа нөмір қосуға тырысыңыз: күтілетін код — `422`.
4. Жарамды дерек жіберіңіз: `201` және жасалған нөмірдің ID-і қайтуы керек.
5. Жоқ ID-ге GET жіберіңіз: күтілетін код — `404`.
