# Зертханалық жұмыс №4

**Тақырып:** толық CRUD, ішінара өзгерту, жою, іздеу және сүзгілеу.

## Мақсат

№3 жұмыстағы оқу және қосу әрекеттерін толықтырып, деректерді қауіпсіз өзгерту мен жоюды, query параметрлерімен іздеуді және қате жағдайларды өңдеуді жүзеге асыру.

## 1. PATCH схемасы

Жаңарту схемасындағы өрістерді өткізіп жіберуге болады. `model_dump(exclude_unset=True)` клиент жібермеген өрістерді жаңартуға қоспайды. Сондықтан тек бағаны жібергенде нөмір белгісі, санаты мен сыйымдылығы сақталады.

`Optional` немесе әдепкі `None` мәні деректер базасындағы міндетті өрісті автоматты қорғамайды. Клиент міндетті өріске нақты `null` жіберсе, схема оны валидация кезінде қабылдамауы тиіс. Бұл «өрісті жібермеу» мен «өріске null жіберу» арасындағы айырма.

## 2. Нөмірді өзгерту

`PATCH /rooms/{room_id}` денесі:

```json
{
  "price_per_night": "24500.00"
}
```

Маршрут ID бойынша жазбаны іздейді. Жоқ болса `404` қайтарады. Бар болса жіберілген өрістерді ғана жаңартып, өзгерісті базаға сақтайды. `GET` арқылы бағаның өзгергенін және қалған өрістердің сақталғанын салыстыруға болады.

ИИ сұрауының үлгісі:

> PATCH /rooms/{room_id} жаса. Бастапқы жазба табылмаса 404 бер. Тек жіберілген өрістерді model_dump(exclude_unset=True) және sqlmodel_update арқылы өзгерт. Теріс баға мен міндетті өрістерге null қабылдама. Санатты ауыстырғанда сыртқы кілттің бар екенін тексер.

## 3. Жою

`DELETE /rooms/{room_id}`:

- жоқ ID — `404`;
- байланысқан брондауы бар нөмір — `409`;
- жоюға болатын нөмір — `204 No Content`.

`204` жауабының денесі болмайды. Нөмірдің брондаулары бар кезде оны бірден жоймау байланысқан деректердің жоғалуын болдырмайды.

Көрсету үшін алдымен брондаусыз жаңа нөмір қосып, соны жойыңыз. Seed деректеріндегі нөмірдің брондауы болуы мүмкін.

## 4. Іздеу және баға бойынша сүзгілеу

`GET /rooms` параметрлері:

| Параметр | Қызметі |
|---|---|
| `search` | Нөмір белгісінің бір бөлігін іздеу |
| `min_price` | Ең төмен түндік баға |
| `max_price` | Ең жоғары түндік баға |
| `category_id` | Бір санаттағы нөмірлер |

Мысал:

```text
http://127.0.0.1:8000/rooms?search=10&min_price=10000&max_price=30000
```

Фильтрлер `select(...).where(...)` түріндегі параметрленген SQLModel сұраулары арқылы орындалады. Пайдаланушы енгізген мәтін SQL жолына тікелей жалғанбайды. Теріс баға шегі немесе төменгі шектің жоғарғы шектен үлкен болуы қате сұрау ретінде тексеріледі.

## 5. Брондау бизнес ережелері

Брондауды жасау кезінде қонақ пен нөмірдің бар болуы тексеріледі. `check_out` күні `check_in` күнінен кейін болуы керек. Бір нөмірдің күшін жоймаған брондаулары `[check_in, check_out)` аралықтарында қабаттаспайды: бір қонақ шыққан күні келесі қонақ келе алады. Қайшылыққа `409` қайтарылады. `cancelled` брондау нөмірді сол мерзімге босатады.

## 6. Қолмен тексеру сценарийі

1. `GET /rooms` нәтижесін және бір нөмірдің бастапқы өрістерін қараңыз.
2. Іздеу мен баға шектерін беріп, нәтижеге тек сәйкес жазбалардың кіретінін тексеріңіз.
3. Жаңа нөмір құрып, оның тек бағасын PATCH арқылы өзгертіңіз.
4. Сол нөмірді GET арқылы қайта алып, қалған өрістерді салыстырыңыз.
5. Нөмірді жойыңыз; сол ID-ге PATCH қайталағанда `404` күтіледі.
6. Бір нөмірге қабаттасатын екі брондау жасаңыз: екіншісі `409` беруі тиіс.

Автоматты тексеру:

```bash
python -m pytest -q
```

Нақты орындалу нәтижелері [тексеру есебінде](verification.md) беріледі. №4 жұмыстың тақырыбында PUT аталғанымен, нұсқаулықтың орындалу қадамдары мен бағалау критерийлері PATCH-ті талап етеді.
