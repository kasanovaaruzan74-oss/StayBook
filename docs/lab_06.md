# Зертханалық жұмыс №6

**Тақырып:** Docker және Docker Compose арқылы компоненттерді контейнерлеу.

## Мақсат

FastAPI мен Streamlit-ті екі жеке контейнерге бөлу, ортақ ішкі желіде байланыстыру және бүкіл жүйені бір командамен іске қосу. SQLite деректерін контейнер өмірінен тәуелсіз сақтау.

## 1. Backend Dockerfile

Түбірдегі `Dockerfile` Python slim образына негізделеді. Алдымен тәуелділіктер файлы көшіріліп, пакеттер орнатылады, одан кейін код қосылады. Осындай реттілік бастапқы код қана өзгергенде пакеттердің орнатылу қабатын кэштен қайта пайдалануға мүмкіндік береді.

Қолданба `uvicorn app.main:app --host 0.0.0.0 --port 8000` арқылы контейнердің барлық интерфейсінде тыңдайды. `EXPOSE 8000` порт туралы метадерек береді; хостқа ашу Compose ішіндегі `ports` арқылы орындалады.

ИИ сұрауының үлгісі:

> Python slim негізінде FastAPI үшін Dockerfile жаса. Алдымен тәуелділіктерді орнатып, кейін бастапқы кодты көшір. Серверді 0.0.0.0:8000 адресінде іске қос. SQLite файлы үшін /data каталогын қолдануға және сыртқы volume қосуға мүмкіндік бер.

## 2. Frontend Dockerfile

`Dockerfile.frontend` Streamlit-ті іске қосады. Негізгі файл — `app/frontend/ui.py`. Тыңдау адресі `0.0.0.0`, порт `8501`. UI сервері API-ге `requests` арқылы қатынасады; SQLite файлын өзі ашпайды.

## 3. Compose сервисі және желі

`docker-compose.yml` екі сервисті біріктіреді:

| Сервис | Қызметі | Хост порты |
|---|---|---|
| `backend` | FastAPI, SQLite, бастапқы деректер | `8000:8000` |
| `frontend` | Streamlit UI | `8501:8501` |

Frontend үшін `BACKEND_URL=http://backend:8000` беріледі. `backend` — Compose желісіндегі сервис атауы, оны Docker-дің ішкі DNS жүйесі контейнер адресіне сәйкестендіреді. Контейнердегі `localhost` сол контейнердің өзін білдіреді; сондықтан frontend басқа контейнердегі API-ге `localhost:8000` арқылы қатынамайды.

`depends_on` пен backend healthcheck көмегімен frontend сервер дайын болғаннан кейін басталады. Бұл API іске қосылып үлгермеген кездегі алғашқы сұрау қатесін азайтады. Кейінгі желі не сервер қатесін UI бәрібір өңдеуі керек.

Compose файлы нұсқаулыққа сәйкес `version: '3.8'` өрісін сақтайды. Заманауи Compose v2 бұл өрістің ескіргені туралы хабарлама беруі мүмкін; ол құрастыру қатесі емес. Қазіргі Compose Specification үшін сервис, желі және volume параметрлері маңызды.

## 4. База деректерін сақтау

SQLite файлы `/data/database.db` жолында, named volume-ға байланыстырылған каталогта сақталады. Контейнерлік URL — `sqlite:////data/database.db`. Контейнерді ауыстыру немесе кәдімгі `docker compose down` орындалуы бұл volume-ды жоймайды. `docker compose down -v` volume-ды жояды, сондықтан оны деректерді сақтау қажет болғанда орындамаймыз.

Базаның контейнерлік жолы `DATABASE_URL` арқылы беріледі. Контейнер іске қосылғанда `python seed.py --if-empty` төрт кесте де бос болса ғана алғашқы 5 мысал жазбаны әр кестеге енгізеді. Кемінде бір кестеде дерек бар болса, қайта іске қосу бизнес деректерін қозғамайды. Бос базаға арналған қауіпсіз тексеруді қолмен де орындауға болады:

```bash
docker compose exec backend python seed.py --if-empty
```

## 5. Бір командамен іске қосу

Docker Desktop іске қосылғанын тексеріңіз. Бұрын жергілікті Uvicorn/Streamlit жұмыс істеп тұрса, оларды `Ctrl+C` арқылы тоқтатыңыз.

```bash
docker compose up --build
```

Ескі Compose v1 орнатылған ортада баламасы — `docker-compose up --build`. Жаңа ортада `docker compose` қолданылады.

- UI: <http://localhost:8501>
- Swagger: <http://localhost:8000/docs>

Күйді және журналдарды тексеру:

```bash
docker compose ps
docker compose logs --tail=80 backend frontend
```

Тоқтату және контейнерлерді қайта құру:

```bash
docker compose down
docker compose up --build
```

UI арқылы жазба қосып, қалыпты `down` және қайта іске қосудан кейін оның сақталғанын тексеріңіз. Нақты Docker тексеруінің жағдайы [verification.md](verification.md) файлында тіркеледі.

## 6. Құрастыруға кірмейтін файлдар

`.dockerignore` виртуалды ортаны, `.git`, жергілікті `*.db`, кэштер мен қажетсіз артефактілерді образға қоспайды. Бұл контекст көлемін азайтып, жергілікті құпия конфигурацияның образға кездейсоқ енуін болдырмайды.

```bash
git add Dockerfile Dockerfile.frontend docker-compose.yml .dockerignore app/
git commit -m "chore: containerize application with Docker and Docker Compose"
git push origin main
```

Бақылау сұрақтарының жауаптары [осында](defense_questions.md#зертханалық-жұмыс-6).
