# Зертханалық жұмыс №7

**Тақырып:** автоматты тесттер, кодты тексеру және жобаны кешенді қорғау.

## Мақсат

API мен бизнес логиканың жұмысын автоматты тексеру, қате жағдайларды бақылау, соңғы README мен есепті дайындау және жүйені толық іске қосып көрсету.

## 1. Тест ортасы

Виртуалды ортада:

```bash
python -m pip install -r requirements-dev.txt
```

`tests/` ішінде `test_api.py` және қосымша сценарийлер бар. Pytest тест функцияларын табады; FastAPI `TestClient` сұрауларды қолданбаға жібереді; HTTPX клиенттік HTTP әрекеттеріне негіз болады. TestClient үшін Uvicorn-ды жеке іске қосу қажет емес.

Тест сессиялары `Depends(get_session)` тәуелділігін ауыстыру арқылы жеке тестілік дерекқорды пайдаланады. Қолданбаның негізгі жұмыс базасын тест барысында тазалауға болмайды.

ИИ сұрауының үлгісі:

> FastAPI қолданбасы үшін TestClient қолданатын pytest интеграциялық тесттерін жаса. GET /rooms 200 және тізім қайтарсын. Жарамды POST /rooms 201 және жасалған жазба қайтарсын. Бөлек тестілік база мен dependency_overrides қолдан. Теріс баға, жоқ ID, PATCH-тегі null, брондау қабаттасуы және сыртқы кілт қателері үшін сценарий қос.

## 2. Тесттерді іске қосу

```bash
pytest
```

Қысқа шығару үшін:

```bash
python -m pytest -q
```

Негізгі тексерілетін әрекеттер:

- GET тізімі және ID бойынша оқу;
- POST және `201` жауабы;
- PATCH бір өрісті өзгертіп, басқаларын сақтауы;
- DELETE және жоқ ID үшін `404`;
- баға, бос мәтін, міндетті өрістер және `null` валидациясы;
- сүзгілердің жұмысы мен баға шектерінің дұрыстығы;
- бірегей мәндердің қайталануына `409`;
- байланысқан негізгі жазбаны жоюға шектеу;
- брондау күндері мен қабаттасуын тексеру;
- seed скриптінің қайталап орындауға жарамдылығы.

Нақты тест саны мен өткен/өтпеген нәтижелер [verification.md](verification.md) файлында берілген. Құжаттағы сценарийлер тізімі тест орындалды дегеннің орнына жүрмейді: қорғауда команданы орындап, нақты нәтижені көрсету керек.

## 3. Код ревьюі

ИИ сұрауының үлгісі:

> Backend кодын қарап шық. Сессиялардың жабылуын, транзакция rollback-ын, SQL сұрауларының параметрленуін, PATCH кезінде null/жіберілмеген өріс айырмасын, сыртқы кілттерді және брондау қабаттасуының жарысу жағдайын тексер. Нақты кодқа сүйенген түзетулер мен оларды дәлелдейтін тесттер ұсын.

Жобада осы мәселелерге арналған тәсілдер:

| Мәселе | Кодтағы тәсіл |
|---|---|
| Сессияның ашық қалуы | `with Session(...)` және `yield` |
| Қате жазудан кейінгі транзакция | `IntegrityError` өңдеу, `rollback()` |
| SQL мәтініне пайдаланушы енгізуін жалғау | SQLModel `select`/`where`, параметрленген шарттар |
| PATCH міндетті өрісті босатуы | Жіберілмеген өрістерді алып тастау және нақты `null`-ды қабылдамау |
| Жоқ сыртқы кілт | Қонақ, нөмір және санаттың бар болуын тексеру |
| Брондаулардың қабаттасуы | Мерзім шарттары және транзакциямен қорғалған жазу |

ИИ қорытындысы әзірлеушінің тексеруін алмастырмайды. Өзгерісті қабылдау үшін код логикасы мен орындалған тест нәтижесі бағаланады.

## 5. Соңғы қорғау сценарийі

1. Docker Desktop іске қосылғанын тексеріңіз. Жергілікті серверлерді тоқтатып, порттарды босатыңыз.
2. `docker compose down` және `docker compose up --build` арқылы контейнерлерді қайта іске қосыңыз. Дерек volume-ын жоймаңыз.
3. `http://localhost:8501` ашып, бастапқы кестені және іздеу нәтижесін көрсетіңіз.
4. Жаңа нөмір қосып, оның бағасын өзгертіңіз; кейін брондаусыз нөмірді жойыңыз.
5. Қонақ пен нөмірді таңдап, дұрыс брондау жасаңыз. Сол нөмірге қабаттасатын мерзіммен брондаудың қабылданбайтынын көрсетіңіз.
6. `http://localhost:8000/docs` арқылы Swagger маршруттарын және `201/404/409/422` жауаптарын түсіндіріңіз.
7. Белсенді виртуалды ортада `pytest` орындаңыз.
8. ER-сызбадағы байланыстарды, модульдердің міндетін және Git тарихын түсіндіріңіз.
